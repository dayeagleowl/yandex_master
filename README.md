## Что это

Мастер-проект: принимает трекинг BlackTrax, пересчитывает позиции гостей в единицы зон и (дальше) раздаёт тайминг, команды и данные на компы зон (слейвы).

## Структура сети `/master`

| Компонент | Статус | Что делает |
|---|---|---|
| `bt_input` | ✅ готов | Приём BlackTrax: **live** (RTTrPM UDP 24002) или **playback** записей тестов из `recordings/`. Выход `OUT_ALL` — полный декодированный поток (`beaconN:tx/ty/tz/...`). |
| `zones` | ✅ готов* | Позиции гостей: метры комнаты, номер зоны, абсолютные метры внутри зоны, относительные 0..1, счётчики по зонам. Выход `OUT_ZONES` (`guestN:...`, `zoneK:count`). *Границы зон в `zones_table` — плейсхолдеры, вписать реальную геометрию после калибровки. |
| `show_control` | ✅ готов | Часы шоу (идут в `running`), приём сессий от тач-панели (OSC, порт 10000, контракт `/panel/...`), таблицы `sessions`/`prompts`, команды зонам (start/restart/reset, общий reset, finish, standby), гейт новой группы (`Gatezones` пусты → `/panel/gate 1`). |
| `osc_dispatch` | ✅ готов* | Рассылка слейвам: `/show/clock`+позиции `Posrate` Гц, команды, `/show/session/start`+`/show/prompt`. Адресация совместима с `osc_zone.tox`. *В таблице `slaves` — локальные плейсхолдеры, вписать реальные IP компов зон. |
| `osc_monitor` | 🔧 отладка | Слушает порт слейва зоны 2 — видно всё, что мастер реально шлёт. |

Внутри каждого компонента лежит `agents_md` — подробная записка. В корне сети — `README_RU`.

## Папки

- `recordings/` — записи тестов BlackTrax (`.bclip` + `.csv` + `.json` + `.mp4`), `test_1` и `test_3`. Плейбек в `bt_input` читает их по относительному пути — папка обязана переезжать вместе с `.toe`.
- `reference_tox/` — компоненты из тестового проекта стороннего подрядчика (`blacktrax_diagnostic/recorder/projection.tox`). **Только референс**: там есть сомнительные решения (приёмник удалялся при каждом сохранении и пересоздавался внешним скриптом по виндовому пути) — не вставлять вслепую.
- `docs/` — передача и пояснения, см. `docs/HANDOFF.md`.

## Сеть площадки (из тестов 26.08)

Сервер BlackTrax `192.168.1.9` → приёмник `192.168.1.32:24002` UDP Unicast. В Unicast поле Network Address не используется (только для Multicast).

## Связка с тач-панелью (проверено вживую 31.08)

`YS_prompt_panel` шлёт OSC на IP мастера, порт **10000** (`Oscaddress`/`Oscport` на `/ys_panel/app`). Мастер принимает `/panel/session/*` и `/panel/guest/K/prompt`, пишет сессии в таблицы и транслирует зонам `/show/session/start` + `/show/prompt` (uuid, гость, promptid, текст). При `Autostartzone1` — автозапуск зоны 1. Обратный канал `/panel/gate 0|1` мастер уже шлёт (порт 10001); приём на стороне панели — TODO.
