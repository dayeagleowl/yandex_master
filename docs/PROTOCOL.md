# Протокол мастера — что идёт на все компы

Спека для тех, кто пишет зонные серверы и тач-панель. Всё через **OSC поверх UDP**. Сверено с кодом мастера 31.08.2026 (`master_project_v1`, коммит `be2a9ce`).

Источник истины в проекте: `show_control/ext_showcontrol` (логика) и `osc_dispatch/ext_oscdispatch` (отправка). Этот файл — их человеческое изложение; при расхождении верен код.

**Машиночитаемая пара:** [`../protocol.json`](../protocol.json) — тот же контракт в JSON (все адреса, типы и описания аргументов, порядок событий). Цифры в нём — IP, порты, границы зон, лимиты — подтягиваются прямо из живого проекта: кнопка **ЭКСПОРТ JSON** в пульте (или `op('/master/export_protocol').module.export()`) переписывает их из таблиц и параметров, так что файл не расходится с тем, что мастер реально шлёт. Тексты пояснений правятся руками и переживают экспорт.

## 1. Кто с кем говорит

| Откуда | Куда | Порт | Что |
|---|---|---|---|
| Мастер `10.10.10.10` | Зона 1 `10.10.10.11` | **6000** | часы, команды, позиции, состав группы |
| Мастер | Зона 2 `10.10.10.12` | **6000** | то же |
| Мастер | Зона 3 `10.10.10.13` | **6000** | то же |
| Мастер | Зона 4 `10.10.10.14` | **6000** | то же |
| Мастер | Тач-панель `10.10.10.15` | **6003** | разрешение пускать новую группу |
| Зона N | Мастер `10.10.10.10` | **6002** | звуковые триггеры, выход промпта из зоны |
| Тач-панель | Мастер `10.10.10.10` | **6001** | сессии и выбранные промпты |
| BlackTrax `10.10.10.16` | Мастер | 24002 | RTTrPM (не OSC, штатный BlackTrax CHOP) |

Адреса и порты зон правятся в таблице `osc_dispatch/slaves` — она же пересобирает отправители. Порты приёма — пары `Panelport` (6001) и `Zonesport` (6002) на `show_control`.

## 2. Мастер → зонам

### 2.1 Общие для всех зон (`/show/...`)

| Адрес | Аргументы | Когда |
|---|---|---|
| `/show/clock` | `seconds:float` | 30 раз в секунду (`Posrate`), пока идёт рассылка |
| `/show/state` | `state:str` — `standby` / `running` / `finished` | при смене состояния шоу |
| `/show/reset` | `1` | оператор нажал СБРОС ВСЕГО |
| `/show/finish` | `1` | оператор нажал FINISH |
| `/show/ping` | `1` | проверка связи (кнопка Testsend) |
| `/show/session/start` | `num:int, uuid:str, guests:int` | группа зарегистрирована; **повторяется при каждой правке привязок** |
| `/show/session/prompt` | `num:int, guest:int, beacon:int, promptid:int, topicid:int, text:str` | по одному на каждого гостя группы, следом за `session/start` |
| `/show/session/end` | `num:int` | группа вышла из тоннеля, номер можно забыть |

`num` — номер сессии (сквозной счётчик), `guest` — 1..3 внутри группы, `beacon` — физический BlackTrax ID. Промпты приходят пачкой; если гость ещё не привязан к бикону, его строка придёт позже — при следующей рассылке состава.

### 2.2 Персонально зоне N (`/zoneN/...`)

| Адрес | Аргументы | Когда |
|---|---|---|
| `/zoneN/start` | `uuid:str, force:int` | запуск сцены зоны |
| `/zoneN/restart` | `uuid:str, force:int` | перезапуск с начала |
| `/zoneN/reset` | `1, force:int` | сброс зоны в исходное |
| `/zoneN/count` | `n:int` | сколько гостей сейчас в зоне (30 Гц) |
| `/zoneN/session/<num>/guest/<idx>/pos` | `zx_rel, zy_rel, zx_abs, zy_abs, x, y :float, beacon:int` | позиция гостя, 30 Гц |
| `/zoneN/unassigned/<beacon>/pos` | те же 6 float | бикон без сессии — виден, но ничей |
| `/zoneN/prompt/enter` | `uuid:str, guest:int, y_rel:float` | промпт въезжает из соседней зоны (ретранслировано мастером) |

**Принудительный режим — флаг `force` последним аргументом у `start` / `restart` / `reset`:**

- `force = 0` — штатно: зона запускается по своей логике, ждёт гостя, уважает свои блокировки.
- `force = 1` — **зона обязана немедленно прервать что делает и выполнить команду с нуля**, игнорируя внутренние блокировки и отсутствие сессии. Это ручка оператора на прогонах и когда зона зависла в своём состоянии.

Включается тумблером **ПРИНУДИТЕЛЬНО** в пульте (`Forcemode` на `show_control`), тогда все команды зонам уходят с `force=1`. Кнопки **ВСЕ: СТАРТ / РЕСТАРТ / СБРОС** шлют команду каждой зоне из таблицы `slaves`. Из кода: `StartZone(2, force=True)`, `AllZones('restart', force=True)`.

**Про позиции — главное.** Номер сессии и номер гостя стоят **в адресе**, а не в аргументах: пока в тоннеле две группы, `guest 2` без сессии двусмысленен. Значения:

- `zx_rel`, `zy_rel` — 0..1 внутри своей зоны (для сцены обычно нужны именно они);
- `zx_abs`, `zy_abs` — метры от угла зоны;
- `x`, `y` — метры тоннеля целиком (0..15 вдоль, 0..3 поперёк);
- `beacon` — физический ID, для отладки.

Тоннель 15 × 3 м, **движение справа налево**: зона 1 — вход справа, зона 4 — выход слева.

### 2.3 Мастер → тач-панели

| Адрес | Аргументы | Смысл |
|---|---|---|
| `/panel/gate` | `0` / `1` | `1` — можно пускать новую группу к выбору промпта |

Гейт открывается, когда зоны из `Gatezones` (по умолчанию 1 и 2) пусты дольше `Gatehold` (4 с) **и** групп в тоннеле меньше `Maxactive` (2). Закрывается мгновенно. Приём этого сообщения на стороне панели ещё не реализован — это её TODO.

## 3. Зоны → мастеру (порт 6002)

| Адрес | Аргументы | Что делает мастер |
|---|---|---|
| `/zoneN/sound/<триггер>` | любые | кладёт в `sound_engine` (лог + дальше проигрывание на Soundcard 6ch) |
| `/zoneN/prompt/exit` | `uuid:str, guest:int, y_rel:float` | ретранслирует зоне N+1 как `/zone{N+1}/prompt/enter` с теми же аргументами |

`prompt/exit` — момент, когда промпт уходит из кадра зоны; следующая зона подхватывает его на своей стороне, чтобы он «въехал из соседней зоны». Из зоны 4 промпт никуда не ретранслируется.

---

## 4. Тач-панель → мастеру (порт 6001)

Контракт панели (проект `YS_prompt_panel`, не меняется):

| Адрес | Аргументы |
|---|---|
| `/panel/session/guests` | `uuid:str, N:int` |
| `/panel/guest/<K>/prompt` | `uuid:str, guest:int, promptid:int, topicid:int, text:str` |
| `/panel/session/start` | `uuid:str, N:int, p1:int, p2:int, p3:int` |
| `/panel/session/end` | `uuid:str` |
| `/panel/session/abort` | `uuid:str` |
| `/panel/screen` | `n:int` (мастер игнорирует) |

`/panel/session/start` — момент, когда мастер заводит группу в реестр и присваивает ей номер.

## 5. Порядок событий одной группы

1. Панель: `/panel/session/guests` → `/panel/guest/K/prompt` (по каждому) → `/panel/session/start`.
2. Мастер выдаёт **номер сессии**, рассылает зонам `/show/session/start` + `/show/session/prompt` на каждого гостя, и (если включено `Autostartzone1`) шлёт `/zone1/start`.
3. Гости входят в зону 1 — мастер привязывает биконы к гостям и **повторяет рассылку состава** (у гостей появляются `beacon`).
4. Пока группа идёт: `/zoneN/session/<num>/guest/<idx>/pos` 30 Гц + `/zoneN/count`, `/show/clock` фоном.
5. Переходы между зонами: зона шлёт `/zoneN/prompt/exit` → мастер шлёт `/zone{N+1}/prompt/enter`.
6. Все биконы группы вне зон дольше `Exitgrace` (8 с) → `/show/session/end [num]`, биконы освобождаются.

## 6. Что должна делать зона (минимум)

- Слушать UDP **6000**, отвечать на `/zoneN/start|restart|reset`.
- **Уважать флаг `force`**: при `force=1` прерывать текущее состояние и стартовать с нуля, не дожидаясь гостя и не проверяя свои блокировки.
- Держать словарь `num → {guest → промпт}` из `/show/session/*`; чистить по `session/end`.
- Рисовать гостей по `/zoneN/session/<num>/guest/<idx>/pos`, беря `zx_rel`/`zy_rel`. Гость, от которого давно нет пакетов (>0.5 с), считается ушедшим.
- Слать `/zoneN/sound/<триггер>` на `10.10.10.10:6002` для звука.
- На выходе промпта из кадра слать `/zoneN/prompt/exit`, чтобы он появился в следующей зоне.

Проверка связи без мастера: любой OSC-монитор на своём порту. В проекте мастера для этого есть `osc_monitor` — направь нужную зону в `slaves` на `127.0.0.1:11002` и увидишь весь её трафик.

## 7. Чего ещё нет

- ArtNet/свет (artgate `2.0.0.14`, artnet spi `2.0.0.12`) — мастером не управляется.
- Сенсоры `10.10.10.17–19` и гравёры `10.10.10.20–21` ходят через зону 4 мимо мастера.
- Приём `/panel/gate` на стороне тач-панели.
- Проигрывание звука на Soundcard 6ch (роутинг триггеров готов, аудио — нет).
